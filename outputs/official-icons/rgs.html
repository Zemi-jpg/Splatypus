1. Overview and Architecture

The project serves as a bridge between radiance-field-based 3D reconstruction models and precise CAD editing environments. It leverages Rhino's native display pipelines via a custom SplatDisplayConduit to render millions of splats efficiently. Rather than treating splats as static viewport graphics, the plugin uses a lightweight proxy point cloud inside the Rhino document. This proxy acts as a coordinate handle, allowing users to move, rotate, scale, or edit the dataset interactively using Rhino's standard transformation tools (such as the Gumball).

2. Key Features and Capabilities

Broad Format Compatibility:

  • Standard Formats: Binary PLY (supporting both point clouds and standard 3D splats) and Lidar LAS.
  • Splat Formats: Compact .splat (32-byte linear), compressed .ksplat (supports multi-section bucket-based compression and custom headers), Spatially Ordered Gaussian (.sog), and Niantic/Scaniverse .spz (supporting both legacy v2 first-three and modern v3 smallest-three quaternion packing decoded from Gzip streams).
  • Streamed Formats: Streamed Spatially Ordered Gaussian (.ssog / .zip). The plugin parses the spatial hierarchical octree index (lod-meta.json) and allows users to selectively import specific Levels of Detail (LOD 0 through LOD 3) to balance visual fidelity with Rhino viewport performance and VRAM usage [1.1.1, 1.2.4].

Adaptive Coordinate and Scale Normalization:

  • On import, the plugin automatically detects coordinates far from the origin and translates the dataset to prevent floating-point viewport jitter.
  • For standard point clouds lacking scale properties, the system runs an adaptive nearest-neighbor density estimation to size the splat particles appropriately for gap-free rendering.

Precision Splat Cropping:

  • Users can crop active splat clouds using standard Rhino boundaries: bounding boxes, closed curves, meshes, Breps, or extrusions.
  • The tool compiles complex boundary geometries into optimized closed meshes, performing rapid spatial point-containment checks.
  • Supports KeepInside and KeepOutside operations, with custom undo/redo states linked back to the display conduit.

Isosurface Mesh Extraction (Splat-to-Mesh):

  • Features an implementation of the Surface Nets algorithm to convert raw splats into textured CAD meshes.
  • Splat data is voxelized into density and color volumes using custom 3D covariance evaluations.
  • An automated Otsu thresholding level-detector estimates optimal iso-values, while Taubin smoothing reduces voxelization artifacts without losing volume.
  • Texturing is achieved by mapping raw trilinear color-weighting back to the extracted mesh vertices.

Synthetic Splat Baking:

  • Allows users to reverse-engineer splat clouds from normal Rhino geometries.
  • Auto-generates camera arrays (exterior orbital domes or interior spherical arrangements) around scene targets.
  • Sequentially repositions the viewport, captures native depth (ZBufferCapture) and color buffers, filters background noise, and projects pixels back into 3D space as flat-facing splats.
     

Supported Import Extensions

These extensions are parsed and loaded into the viewport rendering pipeline or document objects:

.ply (Polygon File Format / Stanford Triangle Format)

  • Supports both structured Gaussian Splat PLY files (with properties like scale_0, rot_0, f_dc_0, and opacity) and standard point clouds (extracting red, green, blue or intensity).

.las (LiDAR Point Cloud Format)

  • Standard aerial or terrestrial LiDAR point cloud files. The parser extracts 3D coordinates, applies offsets/scales from the header, and reads color records (or falls back to grayscale intensity if RGB is unavailable).

.splat (Compact Splat)

  • A streamlined, uncompressed binary format containing linear positions, scales, colors, and quaternions mapped to a 32-byte stride.

.ksplat (Compressed Splat)

  • A compressed splat format designed for web viewers. It supports multi-section structures and bucket-quantized coordinates.

.sog (Spatially Ordered Gaussian)

  • A ZIP-archived splat format featuring a meta.json file and WebP-compressed textures storing quantized position, scale, and spherical harmonics data.

.ssog / .zip (Streamed Spatially Ordered Gaussian)

  • A progressive streamed dataset containing a spatial hierarchy manifest. The importer recursively traverses the node index and loads specific Level of Detail (LOD) chunks, allowing users to choose between maximum detail (LOD 0) and optimized draft views (LOD 1–3) [1.1.1, 1.2.4].

.spz (Niantic/Scaniverse Compressed Splat)

  • A compressed binary format using Gzip streams. The loader parses both legacy v2 (first-three quaternion packing) and v3 (smallest-three quaternion packing) versions.

.webp (WebP Image Format)

  • Decodes WebP images, writes them as a standard .png adjacent to the original file (or in the temp folder), and adds them to the active document as a calibrated Picture Frame.

Supported Export Extensions

These formats are used to write modified, cropped, or synthetically baked splat clouds back to disk:

.ply (Gaussian Splat PLY)

  • Exports active splat datasets back into standard PLY binary format, writing positions (x, y, z), logarithmic scales (scale_0 to scale_2), normalized quaternions (rot_0 to rot_3), base spherical harmonics (f_dc_0 to f_dc_2), and inverse-sigmoid opacities.

.splat (Compact Splat)

  • Writes splat datasets out as flat 32-byte-per-splat binary files.

.ksplat (Compressed KSplat)

  • Writes splats into a single-section uncompressed (Compression Level 0) KSplat structure.
